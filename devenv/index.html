사용하는 사람

동료 교사

선생님이 공유한 페이지와 자료를 봅니다. 각자의 환경은 따로입니다.

학생

폰이나 크롬북으로 안내를 보고, 파일·URL·글을 제출합니다.

Claude 앱 클라우드 개발 로컬 실제 학생 데이터가 사는 곳 코드·공개 안내 기록과 계획

업무별로 어디서 할까

지금까지 이야기한 업무를 모두 모았습니다. 작업대를 골라 그곳에서 하는 일만 볼 수 있습니다.

데이터 경계

이 설계도에서 가장 중요한 부분입니다. 편의보다 이 원칙이 먼저입니다.

Claude가 보는 것

코드, 가짜 학생 데이터, 학생 정보가 없는 공문과 업무 문서까지입니다. 실제 명단, 성적, 상담 내용은 채팅에 붙여넣거나 올리지 않습니다.

실제 학생 데이터의 자리

학교 구글 계정과 내 PC, 두 곳뿐입니다. 처리는 Claude가 가짜 데이터로 완성한 스크립트를 선생님이 직접 실행해서 합니다.

학생 앞 배포는 직접

학생이 쓰는 페이지는 diff를 읽은 뒤 선생님이 배포합니다. Claude는 코드를 제안하고, 배포 명령은 막아 둡니다.

비밀키는 저장소 밖

.env는 커밋하지 않습니다. 클라우드에 필요한 키는 환경의 API credentials에, 학교 PC의 노션 키는 환경변수에 둡니다.

원칙을 실제로 강제하는 설정입니다. 저장소의 .claude/settings.json에 둡니다. CLAUDE.md의 규칙은 부탁이고, 이 설정은 차단입니다.

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./data/real/**)",
      "Read(./**/credentials*.json)",
      "Bash(clasp deploy:*)"
    ]
  }
}

Notion 교무수첩

업무가 들어오는 길과 정리되는 길이 노션 안에서 만납니다.

쿨메신저→ coolwatch →받은 업무함→ 아침 예약 작업 →업무·공문 트래커→Notion Calendar

받은 업무함

coolwatch가 정리한 업무 메시지가 한 줄씩 쌓이는 곳. 할 일·기한·일정이 뽑혀 들어오고, 팝업 대신 보는 조용한 알림창입니다.

업무·공문 트래커

할 일, 마감일, 회의 일시, 상태. 받은 업무함에서 정리되어 들어오고, 날짜는 캘린더에 그대로 보입니다.

수업 설계

단원, 차시, 성취기준, 자료 링크. Claude가 이걸 읽고 PPT와 학습지를 만듭니다.

수행평가 운영

과제, 기간, 루브릭, 제출 페이지 주소, 상태. 학생 개인 점수는 넣지 않고 시트에 둡니다.

프롬프트·스킬 노트

잘 통한 지시문과 실패 기록. 세 번 이상 쓴 지시문은 스킬로 옮깁니다.

하루의 흐름

구조도가 실제 일과에서 움직이는 순서입니다.

  1. 출근길폰으로 오늘 할 일 확인. 새벽에 예약 작업이 받은 업무함을 업무 트래커로 정리해 두었습니다.
  2. 근무 중쿨메신저는 조용히 쌓입니다. 업무 메시지는 coolwatch가 카드로 정리하고 받은 업무함에도 올립니다. 팝업은 꺼 둡니다.
  3. 공강 시간앱에서 수업자료. 수업 설계 DB를 읽혀 슬라이드와 학습지를 만들고, 공문 서식은 HWPX로 올려 채웁니다.
  4. 퇴근 전개발 작업을 클라우드에 맡깁니다. “제출 페이지에 지각 표시 추가”처럼 범위가 분명한 일을 넘기고 노트북을 닫습니다.
  5. 저녁폰으로 진행 확인. 질문이 와 있으면 답합니다.
  6. 다음 날 아침브랜치를 읽고 병합합니다. PR은 자동으로 열리지 않으니 직접 만듭니다.
  7. 수업 전학생용 코드는 Mac에서 배포. clasp push와 clasp deploy를 선생님이 실행합니다.
  8. 수행평가 기간학생 제출과 자동 집계. 파일은 드라이브에, 기록은 시트에 쌓이고, 미제출 확인은 Apps Script 트리거가 구글 안에서 합니다.

도구·MCP·라이브러리

작업대마다 무엇을 쓰는지와 설치 명령입니다.

도입 순서

한꺼번에 다 갖추지 않아도 됩니다. 앞 단계만으로도 바로 쓸모가 있습니다.

  1. 앱과 노션

    “수업자료”, “업무 정리” 프로젝트 두 개를 만들고 노션·구글 커넥터를 연결합니다. 노션에 교무수첩 DB 다섯 개를 만듭니다.

  2. 업무 수집 자동화

    학교 PC에 coolwatch를 설치합니다(설치.bat 한 번). 받은 업무함이 차기 시작하면 아침 정리 예약 작업을 겁니다.

  3. 저장소와 클라우드

    GitHub 비공개 저장소를 만들고 클라우드 세션을 연결합니다. 첫 작업은 가짜 학생 명단, 둘째는 제출 페이지입니다.

  4. 첫 수행평가

    Mac에서 clasp로 제출 페이지를 배포하고, QR을 수업 슬라이드에 넣어 실제로 운영해 봅니다.

저장소 구조

3단계에서 만드는 비공개 저장소입니다. 클라우드 세션과 Mac이 같은 규칙을 읽습니다.

school-workshop/
├── CLAUDE.md                   학교 환경, 한국어, 데이터 경계
├── .claude/
│   ├── settings.json           차단 규칙
│   ├── skills/                 루브릭, 제출폼, 수업 PPT, HWPX 공문
│   └── agents/privacy-reviewer.md   커밋 전 개인정보 점검
├── .mcp.json                   노션·Playwright·Context7 (project 범위)
├── apps-script/                학생 제출 페이지 (clasp 폴더)
├── scripts/                    PPT 일괄 생성, 명단 처리, 집계
├── site/                       GitHub Pages 수업 사이트
├── templates/                  학교 PPT 템플릿, HWPX 서식
├── fixtures/fake_students.csv  가짜 명단
└── data/real/                  .gitignore, Claude 읽기 차단

coolwatch는 학교 PC 전용이라 이 저장소와 따로 둡니다. 받은 압축 파일 안에 소스와 인수인계 문서(HANDOFF.md), 안전 규칙(CLAUDE.md)이 들어 있습니다.

2026년 10월 8일 기준입니다. Claude 앱과 Claude Code의 기능, 설치 방법, 요금과 한도는 바뀔 수 있으니 공식 문서에서 다시 확인하세요. Claude 앱에서 게시한 페이지는 교사와 동료용으로 쓰고, 학생 제출 창구로는 쓰지 않습니다. 학생 정보를 노션이나 외부 서비스로 옮기기 전에는 학교 개인정보 지침을 먼저 확인하세요.
