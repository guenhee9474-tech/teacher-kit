개발환경

연수에서 하는 일은 coolwatch를 쓰는 것과, 수행평가 페이지를 내 계정에 설치해 고쳐 쓰는 것입니다. 여기에는 그에 필요한 환경과, Claude Code와 계획하고 대화하는 방법을 적었습니다.

무엇을 하려면 무엇이 필요한가

수업 자료 만들기브라우저에서 claude.ai에 로그인하면 됩니다. 설치할 것이 없습니다.
coolwatch 쓰기쿨메신저가 깔린 학교 Windows PC에서 설치.bat을 실행합니다. PC에 파이썬이 없으면 설치 파일이 받아 옵니다. Claude 요약을 쓸 때만 Claude Code 설치와 로그인이 필요하고, 처음 설정의 버튼으로 합니다. 노션은 선택입니다. 설명서
수행평가 페이지
설치·수정		노트북(Windows 또는 Mac)에 VS Code, Git, Node.js LTS, Python 3, Claude Code. 그리고 제출물을 받을 구글 계정(학교 계정이 막히면 개인 계정)과 GitHub 계정. 안내
coolwatch 고쳐 쓰기그 PC에 Claude Code를 설치하고 coolwatch 폴더를 엽니다.

Claude는 Pro 또는 Max 요금제 계정으로 로그인합니다.

Claude Code를 쓰는 방법

Claude Code는 여러 모양으로 쓸 수 있습니다. 어느 쪽이든 같은 폴더의 CLAUDE.md를 읽고 같은 일을 합니다. 모두 Pro, Max 같은 유료 요금제 계정이 필요합니다.

터미널터미널에서 claude를 실행해 글로 주고받습니다. 내 PC의 폴더와 명령을 그대로 씁니다. 가장 기본이 되는 방식입니다.
VS Code 확장VS Code 옆 칸에 대화 창이 생깁니다. 고친 곳을 편집기에서 바로 비교해 볼 수 있습니다. 내 PC에서 돕니다.
데스크톱 앱Claude 앱의 Code 탭. 터미널 없이 폴더를 골라 시킵니다. 내 PC에서 돌리거나 클라우드에서 돌리는 것을 고를 수 있습니다.
웹claude.ai/code. 설치 없이 브라우저에서 씁니다. 내 PC가 아니라 Anthropic 쪽에서 돌고, GitHub 저장소를 연결해야 합니다.
JetBrains 플러그인IntelliJ, PyCharm 같은 프로그램을 쓰는 사람용입니다. 연수에서는 다루지 않습니다.

연수에서는 왜 VS Code와 터미널인가

  • 내 PC에서 돌아야 합니다. 수행평가 페이지 설치는 구글 로그인 창을 내 브라우저로 열고, GitHub에 올리고, 자동 시험을 돌립니다. coolwatch는 학교 PC에 있는 쿨메신저 기록을 읽습니다. 웹 방식은 내 PC가 아닌 곳에서 돌아서 이 일을 할 수 없습니다.
  • VS Code는 폴더를 눈으로 보게 해 줍니다. 왼쪽에 파일 목록, 가운데에 파일 내용, 아래에 터미널이 한 창에 있습니다. Claude가 무엇을 고쳤는지 따라가기 쉽습니다.
  • 터미널 방식이 기준입니다. 본보기의 안내 파일과 공식 문서의 명령이 터미널 기준으로 적혀 있습니다. coolwatch의 Claude 요약도 터미널용 claude 명령을 부르므로, 이 설치가 있어야 합니다.
  • 어느 PC에서나 같습니다. 노트북에서도 학교 PC에서도 같은 명령 한 줄로 설치하고 같은 방식으로 씁니다.

VS Code 확장을 함께 깔아도 됩니다. 같은 폴더에서 터미널과 확장을 번갈아 써도 됩니다. 터미널이 낯설면 확장이나 데스크톱 앱으로 시작하고, 설치·배포처럼 명령이 필요한 일만 터미널에서 해도 됩니다.

방법별 설치

터미널아래 “설치와 확인”의 명령 한 줄. Windows에서는 Git for Windows를 함께 깔아 두는 것을 권합니다. 처음 claude를 실행하면 브라우저가 열려 로그인합니다.
VS Code 확장VS Code에서 Ctrl+Shift+X(Mac은 Cmd+Shift+X)로 확장 목록을 열고 “Claude Code”를 검색해 Anthropic이 올린 것을 설치합니다. 확장만으로 대화 창은 쓸 수 있지만, 터미널에서 claude를 치려면 터미널용을 따로 설치해야 합니다.
데스크톱 앱claude.ai/download에서 받아 설치하고, 로그인한 뒤 Code 탭을 엽니다. 따로 설치할 것이 없습니다.
웹설치가 없습니다. claude.ai/code에 로그인하고 GitHub를 연결합니다.
JetBrains 플러그인터미널용을 먼저 설치한 뒤, 프로그램의 Settings → Plugins에서 “Claude Code”를 검색해 설치합니다.

2026년 10월 공식 문서 기준입니다. 설치 방법과 이름은 바뀔 수 있으니 공식 문서에서 다시 확인하세요.

설치와 확인

프로그램을 받는 곳과 설치할 때 고를 것은 연수 전 준비에 있습니다. 터미널용 Claude Code는 아래 명령으로 설치합니다.

# Windows (PowerShell)
irm https://claude.ai/install.ps1 | iex

# Mac (터미널)
curl -fsSL https://claude.ai/install.sh | bash

터미널(Windows는 PowerShell)을 새로 열고 한 줄씩 실행합니다. 네 줄 모두 버전 숫자가 나오면 준비가 끝난 것입니다.

git --version
node -v
python --version
claude --version

만들기 전에 Claude Code와 계획하기

결과를 가르는 것은 코드를 쓰는 시간이 아니라 그 앞의 계획 대화입니다. “만들어 줘”라고만 하면 Claude가 구조를 알아서 정합니다. 계획 대화는 그 결정을 함께 내리는 자리이고, 그러려면 틀이 필요합니다.

틀: 웹 서비스의 네 층

프론트엔드 (화면)사용자가 보고 누르는 것. 사용자의 브라우저에서 돕니다. 수행평가 페이지에서는 HTML 한 파일.
백엔드 (서버)요청을 받아 처리하는 것. 수행평가 페이지에서는 Apps Script 웹 앱.
데이터기억해야 할 것을 두는 곳. 수행평가 페이지에서는 구글 시트와 드라이브.
배포만든 것을 남이 쓸 수 있는 주소에 올리는 일. 수행평가 페이지에서는 GitHub와 구글에 올리기.

계획 대화의 순서

  1. 조건을 말합니다. 누가 쓰는지, 몇 명이 동시에 쓰는지, 비용, 어떤 계정을 쓸지, 어떤 자료가 오가는지.
  2. 계획부터 받습니다. “코드는 아직 쓰지 말고, 프론트엔드·백엔드·데이터·배포를 각각 무엇으로 할지 선택지와 장단점을 줘. 정해야 할 것은 나에게 물어봐.”
  3. 자료가 가는 길을 묻습니다. “무엇이 어디에 저장되고 어디로 나가?” 학생 정보가 있으면 이것이 구조를 정합니다.
  4. 확인 방법을 정합니다. “무엇이 되면 완성이야? 고친 뒤 멀쩡한지 어떻게 시험해?”
  5. 적어 두게 합니다. “정한 구조와 이유를 CLAUDE.md에 적어 줘.”

Claude Code에는 파일을 고치지 않고 계획만 세우는 계획 모드가 있습니다.

층마다 물어볼 것

요청새 기능은 프론트엔드가 백엔드에 무엇을 새로 묻는 일인가.
상태이 값은 어디에 저장되나. 기기와 서버가 다르면 누구를 믿나.
프론트엔드과제 내용은 설정 한 곳으로 빼 두었나. 브라우저가 이 사건을 알려 주나, 막을 수 있나, 기록만 되나.
백엔드·데이터몇 명이 동시에 쓰나. 누가 누구의 글을 볼 수 있어야 하나.
신뢰이 값은 사용자에게 보여도 되나. 누가 이 요청을 보낼 수 있나.
배포·시험어디에 어떻게 올리나. 고친 뒤 멀쩡한지 무엇으로 확인하나.

고칠 때도 같은 틀로

“안 돼”라고만 하면 Claude는 네 층을 모두 뒤져야 합니다. 어디까지는 되고 어디부터 안 되는지를 말합니다.

고쳤는데 옛 화면이 뜬다배포. 화면 아래의 버전 글자를 봅니다.
기기에는 남는데 시트에 줄이 없다요청이나 백엔드. 시트의 오류 탭을 봅니다.
시트에는 있는데 PDF가 없다백엔드. 시트의 오류 탭을 봅니다.
버튼이 안 눌린다프론트엔드. 그 화면 자체를 봅니다.

일하는 방식

계획이 서면 아래 순서로 만듭니다. 이미 있는 폴더를 고칠 때도 같습니다.

  1. 받은 폴더를 VS Code로 엽니다.
  2. VS Code의 터미널에서 claude를 실행합니다.
  3. 할 일을 말로 시킵니다.
    • “CLAUDE.md의 처음 설치를 진행해 줘”
    • “예시문과 Word Bank를 이 내용으로 바꿔 줘”
    • “테스트 돌리고 배포해 줘”
  4. Claude가 파일을 고치고 자동 시험을 돌립니다. 브라우저에서 눌러야 하는 것은 무엇을 누르는지 알려 줍니다.
  5. 결과는 내가 화면으로 확인합니다. 학생 페이지를 열어 직접 한 번 해 봅니다.

이 방식을 받치는 세 가지

CLAUDE.mdClaude가 폴더를 열 때마다 읽는 규칙입니다. 구조, 바꾸면 안 되는 것, 실제로 겪은 문제가 적혀 있습니다.
자동 시험고친 것이 다른 곳을 망가뜨리지 않았는지 확인합니다. 지어낸 자료와 가짜 서버로 돌립니다.
git바꾼 내용을 기록으로 남겨, 잘못되면 되돌릴 수 있게 합니다.

수행평가 본보기 폴더

english-writing/
├── docs/index.html     학생 페이지 (GitHub Pages가 이 폴더를 보여 줌)
├── docs/teacher.html   교사 현황 화면
├── gas/Code.gs         Apps Script 웹 앱 (저장, PDF, 시트, 사전)
├── tests/              자동 시험
├── scripts/deploy.sh   GitHub 올리기와 Apps Script 재배포를 한 번에
└── CLAUDE.md           Claude Code가 읽는 설명서와 규칙

배포 규칙

  • 배포는 선생님이 “배포해 줘”라고 말할 때만 Claude Code가 deploy.sh로 합니다.
  • 수업 전날까지 마치고, 태블릿으로 로그인 화면 아래 버전 글자를 확인합니다. 수업 당일 아침에는 배포하지 않습니다.
  • Apps Script 편집기에 코드를 직접 붙여넣지 않습니다. 폴더의 코드와 어긋납니다.
  • GitHub 저장소는 공개입니다. 학생 정보와 비밀값을 넣지 않습니다.

자료가 가는 길

쿨메신저 업무 메시지학교 PC 안에 정리됩니다. 제외 단어가 든 글은 기록하지 않습니다. Claude 요약을 켜면 남은 글의 본문이 Anthropic(Claude)으로, 노션 연결을 하면 정리된 글이 노션으로 갑니다. 단어로 거르는 것이라 완벽하지 않습니다.
학생 제출물이름·학번·글이 제출물을 받는 구글 계정의 드라이브와 시트에 쌓입니다. GitHub에는 페이지 코드만 올라갑니다. 학생이 사전에서 찾은 단어는 사전·번역 서비스로 갑니다.
명단·성적·상담원래 있던 곳에 둡니다. Claude에 붙여넣거나 올리지 않고, 저장소에도 넣지 않습니다.
비밀키저장소에 넣지 않습니다. coolwatch의 노션 키는 학교 PC의 환경변수에 둡니다. 수행평가 페이지의 token과 교사 PIN은 페이지 소스에 보이는 값이라 비밀이 아닙니다.

개발과 시험은 지어낸 자료로 합니다. 학생 정보를 구글 드라이브나 노션에 두기 전에는 학교 개인정보 지침을 먼저 확인하세요.

자주 막히는 곳

학교 망에서 설치 사이트가 열리지 않습니다
claude.ai, github.com, python.org 같은 곳이 막혀 있으면 설치가 멈춥니다. 연수 전에 미리 설치해 오고, 압축 파일은 USB로도 받을 수 있게 준비합니다.
학교 구글 계정으로 웹 앱이 열리지 않습니다
“모든 사용자”에게 웹 앱을 여는 것이 관리자 설정으로 막혀 있을 수 있습니다. 막히면 개인 계정을 씁니다.
권한 승인 때 “안전하지 않음” 경고가 뜹니다
본인 계정에 본인이 올린 스크립트라서 뜨는 것입니다. “고급”을 눌러 계속 진행하고 허용합니다.
Windows에서 bash scripts/deploy.sh가 실행되지 않습니다
Git을 설치할 때 함께 깔리는 Git Bash가 필요합니다.
배포했는데 학생 화면이 옛 버전입니다
GitHub Pages 반영에 최대 10분이 걸립니다. Safari가 옛 화면을 붙들고 있으면 주소 뒤에 ?v=숫자를 붙여 엽니다.
